# Проєкт Findex

Пошуковий рушій та аналізатор текстових корпусів, побудований на принципах потокової обробки даних (streaming).

## Порівняння алгоритмів (Streaming vs Greedy)

Аналіз проводився на корпусі з 15 книг загальним об'ємом близько 3.87 млн токенів.

| Метрика | Streaming (Потоковий) | Greedy (Жадібний) |
|---|---|---|
| **Кількість документів** | 15 | 15 |
| **Усього токенів** | 3 872 573 | 3 872 573 |
| **Унікальних слів (словник)** | 69 030 | 69 030 |
| **Час виконання** | 15.55 сек | 10.69 сек |
| **Пікова пам'ять** | **92.35 MB** | **239.38 MB** |

---

### Аналіз використання ресурсів

#### 1. Куди пішла пам'ять у Greedy версії (239.38 MB)?
* **Масив `documents`**: Усі 15 книг зберігаються у пам'яті одночасно як великі текстові рядки.
* **Масив `all_tokens`**: Жадібний підхід створює єдиний список із **3 872 573 окремих об'єктів-рядків**. У CPython кожен рядок типу `str` займає щонайменше 49–50 байт додаткових службових даних, плюс 8 байт під вказівник у списку. Тільки зберігання цього списку вимагає понад 200 МБ оперативної пам'яті.
* **Дублювання об'єктів**: `Counter` створюється поверх уже існуючого гігантського списку токенів, що спричиняє піковий стрибок пам'яті.

#### 2. За рахунок чого заощаджує Streaming (92.35 MB)?
* Генератор `iter_documents` зчитує книги по черзі та звільняє пам'ять від попереднього тексту.
* Генератор `tokenize` передає токени у `Counter` по одному (`yield`), не створюючи проміжних списків на мільйони елементів.
* Основний об'єм пам'яті в 92.35 MB займає лише об'єкт `Counter` (в якому зберігається 69 030 унікальних термінів) та поточний файл, що читається.

#### 3. Чому Greedy виявився трохи швидшим за часом (10.69 сек проти 15.55 сек)?
Жадібний підхід працює швидше за рахунок використання суцільних масивів пам'яті та нативних C-оптимізацій Python під час виклику `.extend()`. Потоковий підхід витрачає додатковий час на накладні витрати (overhead) ітерацій генераторів `yield` та регулярні виклики I/O при відкритті й закритті файлів, що є класичним компромісом (trade-off) між швидкістю та використанням пам'яті.
